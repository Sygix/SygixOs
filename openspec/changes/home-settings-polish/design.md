# Design

## Context
Voir `proposal.md` (« Why »). État du code sur `main` après le merge de la PR #17 (`fix/home-ui-bugs`) et l'archivage de `home-ui-bugfixes`, vérifié fichier par fichier :

- **Transition héro ↔ grille** (`HomeScreen.kt` (`ui.home`), `LauncherHome`) : trois couches empilées dans un `Box` plein écran (`HeroStage`, `AmbientGradient`, `HomeGrid`), plus le `Dock` aligné en bas de l'écran. Le passage de zone anime deux alphas (`heroAlpha`, `gridAlpha`, `tween(Motion.LAYER_FADE_MS, AppleEasing)`) ; le dock reçoit `heroAlpha`, le dégradé et la grille `gridAlpha`. Chaque couche est une `hazeSource` (verre du dock et du menu). `HeroStage` reçoit `active` (focus) et `visible` (lecture vidéo, Ken Burns, avance automatique) dérivés de `zone != GRID`. `Dock` dérive `active` du verre de `alpha > 0.01f`.
- **Engrenage** (`HomeScreen.kt`, `SettingsGear` / `GearIcon`) : engrenage plein blanc opaque, dessiné sans fond (`drawWithCache` + chemin mis en cache), aligné en haut à droite de l'écran dans un `AnimatedVisibility(visible = zone != GRID)` en `fadeIn` / `fadeOut` de `Motion.LAYER_FADE_MS` : il quitte la composition en zone grille.
- **Grille** (`HomeGrid.kt` (`ui.home`)) : `Column` avec `verticalScroll(scrollState)` propre à la grille, sous un `LocalBringIntoViewSpec` qui neutralise le défilement automatique au focus (`NoAutoScroll`) : la seule autorité de défilement est la règle pure `domain/GridScroll.kt`. `GridScroll.next(anchor, row, openRow, viewport)` calcule la position qui garde le bloc focusé (rangée, plus le panneau Top Shelf ouvert au-dessus) entre les marges, avec un plancher fixé à 0 (`coerceAtLeast(0f)`) ; `LaunchedEffect(openRow, focusedApp)` l'applique par `animateScrollBy` (`Motion.SHELF_EXPAND_MS`). La position n'est plus remise à zéro en quittant la zone (seul le panneau se referme). `gridRow` (rangée focusée) remonte à `LauncherHome` pour décider que haut depuis la rangée 0 quitte la grille.
- **Repli de focus** (`domain/FocusFallback.kt`, `ui/home/TileFocus.kt`) : dock et grille partagent `rememberTileFocus`, qui mémorise la dernière tuile visitée, choisit la tuile d'entrée et reporte le focus sur la voisine quand l'app focusée disparaît ; `LauncherHome` rend le focus au héro quand la zone active se vide.
- **Réglages** (`SettingsScreen.kt` (`ui.settings`)) : `pane` (CATEGORIES / CONTENT) et `hiddenSubScreen` ; la catégorie « Applications cachées » n'affiche qu'un bouton d'entrée (`HiddenCategoryContent`, testTag `open-hidden`) qui ouvre `HiddenAppsScreen` (plein écran, zIndex 22, bouton « Tout réactiver » **sous** la liste, ligne retirée dès la réactivation, focus reporté sur la voisine). `Key.Back` ferme les réglages depuis n'importe quel volet ; droite sur une catégorie dont le contenu n'a rien de focalisable laisse le focus sur la catégorie (`contentFocus.tryRequestFocus()` échoue → `pane = CATEGORIES`).
- **État des réglages** (`SettingsViewModel.kt` (`ui.settings`)) : `state` combine `disabledSources`, `allApps`, `hidden` ; les deux listes sont triées par `label.lowercase()` ; `hiddenApps` est le filtre de cette liste. Les compteurs sont un `StateFlow` **séparé** (`counts`, `programCountsFlow()` de `TvProviderHeroSource` partagé avec `WhileSubscribed(5_000)` et une valeur initiale `emptyMap()` : pas de scan tant que les réglages ne sont pas affichés), lu ligne par ligne via `derivedStateOf` pour ne recomposer que la ligne dont le compte change. `programCounts()` ne compte que les `PreviewPrograms` browsables (pas les `WatchNextPrograms`) : le tri utilise ce compteur tel qu'affiché (périmètre : question ouverte de `p2c-upnext`, hors de ce change).
- **Persistance** (`data/LauncherPrefs.kt`) : `hidden_apps` est un `stringSetPreferencesKey` ; `hideApps` retire aussi l'épinglage dans le même `edit` ; `updateGridOrder` lit l'ensemble caché pour conserver la position des apps cachées ; `unhideApps` / `setHidden(emptySet())` pour la réactivation. Aucune date nulle part.

## Goals / Non-Goals
**Goals :**
- Une seule animation de défilement pour héro ↔ grille, pilotée par un seul état, sans double défilement ni remise à zéro brutale.
- Le dock est géométriquement solidaire du héro (même translation), donc jamais sur la grille, sans logique d'alpha.
- Le volet « Applications cachées » réutilise la mécanique de contenu de volet existante (`SourcesContent`), avec une liste affichée découplée de l'état persisté.
- Tri en fonctions pures testables en JUnit ; dates de masquage persistées de façon additive et rétro-compatible.

**Non-goals :**
- Ne pas réécrire la logique du Top Shelf ni la sélection des apps sources ; ne pas toucher aux corrections de `fix/home-ui-bugs`.

## Decisions

### D1. Page d'un seul tenant : un seul `ScrollState` pour héro + grille
- `LauncherHome` mesure le viewport (`BoxWithConstraints`) et compose une `Column` défilante (`verticalScroll(pageScroll, enabled = false)` : défilement uniquement programmatique, ni molette ni geste) : premier enfant, le bloc héro à hauteur exacte du viewport, qui contient `HeroStage`, le dock (aligné en bas de ce bloc, pas de l'écran) et l'engrenage (aligné en haut à droite de ce bloc) ; second enfant, le bloc grille (hauteur au moins égale au viewport) sur le dégradé neutre. `pageScroll` est le seul `ScrollState` de l'accueil : `HomeGrid` perd son `verticalScroll` propre.
- `LocalBringIntoViewSpec` neutralisé (`NoAutoScroll`, déplacé de `HomeGrid` vers `LauncherHome`) sur **toute la page**, pas seulement sur la grille : le focus qui arrive sur le héro, le dock, l'engrenage ou une tuile ne déclenche jamais de défilement implicite ; la page ne bouge que par la règle de D2. Les réglages et le menu contextuel restent hors de la page (leurs listes gardent le défilement au focus par défaut).
- **Plancher paramétrable de `GridScroll`** : `rowTop` et `next` prennent un paramètre `origin` (défaut 0, les tests de la PR #17 restent valables tels quels), le haut du bloc grille dans la page (hauteur du héro). Les positions sont exprimées dans la page ; `next` part de `origin` sans ancre et ne descend jamais sous `origin` (`coerceAtLeast(origin)` au lieu de `coerceAtLeast(0f)`) : tant que la grille est active, la page ne remonte jamais au-dessus du début de la grille.
- `HomeGrid` reçoit `origin`, `viewport` (mesurés par `LauncherHome`) et l'ancre courante, et remonte la nouvelle ancre (`onAnchor`) au lieu d'animer lui-même : la règle « focus toujours visible » du Top Shelf est inchangée, seule sa base change.
- Alternative rejetée : garder deux défilements (page + grille) — double autorité de défilement, et l'état de la page dépend de deux sources.
- Alternative rejetée : `graphicsLayer { translationY }` sur les couches sans `ScrollState` — plus léger, mais la grille défilante devrait alors être clipée et son propre défilement coordonné à la main ; un `ScrollState` unique donne gratuitement `animateScrollTo`, l'interruption (« continuité de l'animation ») et la compatibilité avec le calcul du Top Shelf.

### D2. Cible de la page, interruption et durées
- Fonction pure `domain/HomePage.kt` : `target(gridActive, anchor, origin)` = 0 si la zone grille n'est pas active, sinon l'ancre de `GridScroll` (au moins `origin`), ou `origin` sans ancre. `transition(previousGridActive, gridActive)` classe chaque changement de cible : `SNAP` (première composition, pas d'animation), `ZONE` (la zone grille devient active ou inactive), `SAME_ZONE` (défilement dans la grille). `zone` reste la seule source de vérité du focus ; la position de la page en dérive.
- Un seul `LaunchedEffect` dans `LauncherHome` collecte `snapshotFlow { zone, ancre }` avec `collectLatest` et applique la cible : `scrollTo` pour `SNAP`, `animateScrollTo(target, tween(Motion.PAGE_SCROLL_MS, AppleEasing))` pour `ZONE` (valeur de l'ancien `LAYER_FADE_MS`, 400 ms, dans la plage « Focus tvOS » ; la constante est renommée), `tween(Motion.SHELF_EXPAND_MS, AppleEasing)` pour `GRID` (durée de l'expansion du panneau, « Panneau Top Shelf au focus »).
- Toute pression haut/bas/Retour change la cible ; `collectLatest` annule l'animation en cours et repart de la position courante (« continuité de l'animation »). La transition précédente est une variable locale de l'effet, pas un état hors snapshot.
- Retour depuis une rangée profonde : une seule `animateScrollTo(0)` à durée fixe (la vitesse varie avec la distance, comme le défilement Top Shelf existant).
- Sortie et retour dans la grille (décision de Sygix : position laissée, pas un écran exactement) : l'ancre n'est pas remise à zéro (acquis de la PR #17) ; à la sortie la cible devient 0, au retour elle redevient l'ancre, donc la page redescend jusqu'à la position de la grille laissée à la sortie. Le panneau se referme à la sortie (inchangé) et l'ancre est recalculée par `GridScroll` pendant que la page remonte, la rangée focusée gardant sa place.
- Ni `pageScroll.value` ni l'ancre ne sont lus en composition : la cible est calculée dans le `snapshotFlow`, et `HomeGrid` reçoit l'ancre sous forme de lambda (`anchor: () -> Anchor?`) lue dans son effet. Un changement de rangée ne recompose donc pas `LauncherHome`, et le défilement ne recompose pas les tuiles à chaque frame. Seule exception, voulue : `heroOnScreen` (D3), un `derivedStateOf` qui ne change qu'une fois par traversée.

### D3. Visibilité du héro et économie de ressources dérivées de la zone
- `HeroStage.visible` = `zone != GRID` (inchangé : pause dès qu'on part vers la grille, reprise dès qu'on remonte). La libération du lecteur (« Préchargement et mémoire ») reste déclenchée par la zone : le héro est hors écran à la fin de l'animation et en pause dès son début.
- Verre du dock (décision de Sygix : actif tant que le dock est visible) : `Dock.active` = `heroOnScreen`, un `derivedStateOf { HomePage.heroOnScreen(pageScroll.value, hauteur du héro) }` (vrai tant que la page a défilé de moins que la hauteur du héro, arrondie comme la mise en page). Il ne bascule qu'une fois par traversée : à la descente, quand le héro sort entièrement de l'écran ; à la remontée, dès le premier pixel du héro. Le dock garde donc le même matériau pendant tout le défilement ; le paramètre `alpha` du dock est supprimé.
- `GlassSurface` garde une seule structure : un seul `Box`, dont seul le modificateur change (`hazeGlass` ou fond de repli). Le contenu (les tuiles du dock) n'est jamais recréé à la bascule, et le focus d'une tuile est conservé. La surface expose son état par la propriété sémantique `GlassActive` (testTag `dock-glass` pour le dock), qui ne sert qu'aux tests et n'est pas exposée à l'accessibilité.
- Coût assumé : pendant la descente et la remontée, le flou du dock est recalculé à chaque frame tant que le héro est visible. Sources de saccades à mesurer sur la TV (`assembleRelease`, tâche 5.1) : flou Haze pendant le défilement, Ken Burns / vidéo du héro encore en cours au premier frame.

### D4. Engrenage solidaire du héro
- `SettingsGear` garde son dessin de la PR #17 (engrenage plein blanc opaque, sans fond ni verre). Il est composé **dans** le bloc héro (aligné en haut à droite de ce bloc), comme le dock, et l'`AnimatedVisibility` en fondu est supprimé : il suit la translation de la page sans logique propre, sort par le haut à la descente et n'est jamais visible en vue grille (« Icône réglages flottante » de `settings`). Il reste composé (hors écran) en vue grille ; son focus n'est actif que quand `zone == HERO` (inchangé). Il n'est retiré de la composition que pendant l'affichage des réglages, comme aujourd'hui.

### D5. Volet « Applications cachées » : liste affichée découplée de l'état persisté
- `SettingsViewModel` expose `hiddenRows: List<HiddenRow>` (`HiddenRow(app, hidden: Boolean, hiddenAt: Long?)`). La **composition** de la liste (quelles apps, dans quel ordre) est un instantané pris au moment du recalcul ; l'**état** `hidden` de chaque ligne est vivant (combiné au flux `hidden` de `LauncherPrefs`), ce qui donne le switch « visible » sans retirer la ligne.
- Un seul point d'entrée `refreshHiddenRows()` recalcule l'instantané (tri de D7). La spec recalcule la liste à chaque **entrée** dans la catégorie (catégorie devenue active, y compris à l'ouverture des réglages) ; elle reste inchangée tant que la catégorie est active. L'entrée couvre aussi les apps cachées depuis l'accueil entre deux ouvertures. `SettingsScreen` appelle le ViewModel (`enterCategory(category)`, qui délègue à `refreshHiddenRows()` ou à l'instantané d'« Apps sources » de D7) **dans le gestionnaire de touches** qui change la catégorie (`selectCategory`), et l'engrenage l'appelle pour `SettingsCategory.Initial` juste avant d'ouvrir les réglages : l'appel est synchrone, avant la recomposition, et pas dans un `LaunchedEffect` qui ne s'exécuterait qu'après la première image. Les passages de focus entre volets (`pane`) ne déclenchent rien. L'instantané est calculé de façon synchrone à partir des dernières valeurs connues (apps installées et apps cachées datées, partagées en `StateFlow`), et `state` est mis à jour sur `Dispatchers.Main.immediate` avant l'image suivante : aucune image n'affiche l'ancienne liste (test « coming back to the category never shows the previous list »).
- OK sur une ligne : un seul callback `onToggle(pkg)` vers `SettingsViewModel.toggleHidden(pkg)`, qui délègue à `LauncherPrefs.toggleHidden` : lecture de l'ensemble caché et écriture dans le même `edit` DataStore (masquage daté et désépinglage, ou réactivation). La décision ne se prend ni dans le composable ni sur un état d'UI potentiellement en retard. « Tout réactiver » (décision de Sygix : liste affichée seulement) : `unhideAll()` réactive les apps de l'instantané, pas l'ensemble persisté ; une app cachée puis désinstallée reste cachée. `AppCatalogRepository.unhideAll()` et `unhideApp()`, devenus sans appelant, sont supprimés.
- App désinstallée pendant l'affichage (décision de Sygix) : la ligne disparaît de l'instantané (filtré par les apps installées). `HiddenContent` réutilise `TileFocus` (`ui/home/TileFocus.kt`, donc `FocusFallback`) : il mémorise la dernière ligne focalisée et son index ; quand la liste des packages change alors qu'une ligne avait le focus (pas « Tout réactiver », pas le volet gauche), le focus va à `FocusFallback.entry`, c'est-à-dire la même ligne si elle existe encore, sinon celle qui occupe son index (bornée à la dernière). Si la liste devient vide, `SettingsScreen` repasse `pane` à `CATEGORIES` dès que `SettingsState.canEnter(catégorie)` devient faux, ce qui rend le focus à la catégorie ; la même règle (`canEnter`) sert la garde de Droite sur une catégorie vide.
- Alternative rejetée : garder une liste dérivée du flux `hidden` et « geler » les lignes en cours de retrait avec un délai — état dupliqué et non déterministe.

### D6. Volet « Applications cachées » : UI
- `HiddenAppsScreen` supprimé ; nouveau `HiddenContent` dans `SettingsContent.kt` : `LazyColumn` (`listState` de `SettingsScreen`, comme `SourcesContent`) avec en premier item le bouton « Tout réactiver » (`SettingsEntryButton` existant, testTag `unhide-all`, qui signale son focus pour la règle de D5), puis une ligne par `HiddenRow` (`tvFocus` + `tvClickable`, `AppleSwitch(checked = row.hidden)`, testTags `hidden-row-<pkg>` / `hidden-switch-<pkg>`), sémantique `Role.Switch` + `toggleableState` reflétant `hidden`, nom de l'app dans le nœud fusionné. Conteneur testTag `hidden-pane`. État vide : seul un texte centré testTag `hidden-empty` est rendu, rien de focalisable ; droite ne quitte pas la catégorie (même garde que « Apps sources » vide dans `enterContent`, car une `LazyColumn` absente ne peut pas recevoir `contentFocus`).
- `contentFocus` est posé sur la **première ligne** (premier `HiddenRow`), pas sur le bouton : haut depuis la première ligne atteint « Tout réactiver » par le déplacement naturel de la `LazyColumn`. C'est l'exception de « Page de réglages » ; les autres catégories gardent `contentFocus` sur leur premier élément.
- `SettingsScreen` : suppression de `hiddenSubScreen` et de la branche `Key.Back` associée ; les bords haut/bas restent gérés par la `LazyColumn` (pas de boucle) ; gauche → `pane = CATEGORIES` (existant).
- Chaînes : libellés déjà en dur dans `SettingsContent.kt` (« Aucune application cachée », « Tout réactiver ») et dans `SettingsScreen.kt` (libellé de catégorie « Applications cachées ») ; les passer en ressources FR (`strings.xml`, créé par ce change) pour les chaînes touchées. Les libellés des trois catégories passent ensemble en ressources, pour que l'énumération reste homogène, et les en-têtes des volets réutilisent ces mêmes ressources (« Apps sources », « Applications cachées », « À propos ») au lieu de les répéter en dur ; le titre « Réglages » (page et description de l'engrenage) et la description d'« Apps sources » passent aussi en ressources. `hiddenCountLabel`, qui ne servait qu'au bouton d'entrée du sous-écran, est supprimé.

### D7. Tri : fonctions pures dans `domain/`
- `SettingsOrdering.sources(apps, counts: Map<String, Int>)` : partition `count > 0` / `count == 0` ; première partie par `count` décroissant puis `label.lowercase()` à égalité, seconde par `label.lowercase()`.
- `SettingsOrdering.hidden(apps, dates: Map<String, Long>)` : datées par `hiddenAt` décroissant, puis non datées par `label.lowercase()`.
- Pour « Apps sources », l'ordre est calculé sur un **instantané des compteurs** pris à l'entrée dans la catégorie (même déclencheur que D5 : la catégorie « Apps sources » devient active, y compris à l'ouverture des réglages) : `state` combine cet instantané (`sourceCounts`), jamais `counts` directement, donc une nouvelle émission ne réordonne rien, et la bascule d'un switch ne change pas la position de la ligne. Le compteur affiché par ligne reste lu via `derivedStateOf` comme aujourd'hui et se met à jour sur place.
- **Comptage au lancement, en pause en arrière-plan** (décision de Sygix) : `counts` garde le même `programCountsFlow()` (un seul `ContentObserver`, aucune seconde lecture du TV Provider), partagé avec `SharingStarted.WhileSubscribed()` (arrêt immédiat, dernière valeur conservée). Son seul abonné est `LauncherHome`, qui le collecte avec `collectAsStateWithLifecycle()` dès sa composition, que les réglages soient ouverts ou non : la collecte démarre avec l'accueil au lancement, s'arrête à `ON_STOP` (le `channelFlow` désinscrit l'observateur dans son `finally`) et reprend à `ON_START`, où `programCountsFlow()` envoie aussitôt un nouveau comptage. Il n'y a plus de `SharingStarted.Eagerly` ni de collecteur dans `init` : un abonnement permanent rendrait la pause impossible. La valeur initiale reste `null` (`StateFlow<Map<String, Int>?>`) pour distinguer « pas encore compté » de « compté, vide » ; les lignes affichent 0 tant qu'elle vaut `null`. `SettingsViewModel` reçoit ce flux en paramètre (la `Factory` passe `tvProvider.programCountsFlow()`) pour que les tests injectent un flux contrôlé.
- **Retri unique** : si `counts` vaut `null` à l'entrée, l'instantané vaut `null` (« en attente ») et la liste est alphabétique ; la première valeur non nulle remplit l'instantané une seule fois (`onEach { sourceCounts.update { it ?: latest } }` sur le flux partagé, donc seulement pendant la collecte), ce qui retrie la liste avec `SettingsOrdering.sources` ; les émissions suivantes, y compris le nouveau comptage au retour au premier plan, ne touchent plus l'instantané. Le focus suit l'app, pas l'index : les items de la `LazyColumn` ont pour clé le package, l'item focusé reste composé (épinglage du focus de `LazyColumn`) et garde le focus après le déplacement. `SourcesContent` attend l'image suivante (mise en page du nouvel ordre), puis, si la clé de la ligne focusée n'est pas parmi les éléments visibles, défile jusqu'à son index ; ce calcul est la fonction pure `ListReveal.indexToReveal` (`domain/`), avec la constante nommée `LeadingItems` (l'en-tête du volet) au lieu d'un `+1`.

### D8. Persistance des dates de masquage : clé additive, l'ensemble reste la vérité
- `hidden_apps` (ensemble) reste la source de vérité de l'appartenance : `catalog`, `updateGridOrder`, `unhideApps`, `setHidden` continuent de le lire et de l'écrire sans changement.
- Nouvelle clé `hidden_apps_dates` (`stringPreferencesKey`, lignes `package\tepochMillis`, mêmes séparateurs `LINE` / `FIELD` que `cached_apps`). `hideApps(vararg)` écrit l'ensemble **et** la date (`clock()` injecté, défaut `System.currentTimeMillis`) dans le même `edit` ; `unhideApps` retire l'entrée de date ; `setHidden(emptySet())` vide aussi les dates.
- Lecture : `hiddenWithDates: Flow<Map<String, Long?>>` = chaque package de l'ensemble, associé à sa date si présente, `null` sinon. Une entrée de date sans package dans l'ensemble est ignorée (et nettoyée à la prochaine écriture). Aucune migration au démarrage : l'ancien format est lu tel quel, l'app sans date est « sans date » jusqu'à un nouveau masquage.
- Alternative rejetée : remplacer l'ensemble par une map sérialisée et migrer au premier démarrage — touche quatre lecteurs de l'ensemble, une migration à tester et à rendre idempotente, sans bénéfice.

## Risks / Trade-offs
- [Saccades persistantes malgré le défilement] → mesurer sur la TV en `assembleRelease` avec, un à un : flou Haze désactivé pendant l'animation, vidéo du héro mise en pause avant le premier frame, `pageScroll.value` lu hors composition ; conserver la combinaison la plus fluide, documentée dans la PR.
- [Calcul Top Shelf dépendant de la hauteur du héro] → la hauteur est celle du viewport (`BoxWithConstraints`) ; test Compose à la taille TV vérifiant que la rangée focusée reste visible avec panneau ouvert après le changement de base de défilement.
- [Interruption de l'animation laissant la page entre deux positions] → la cible ne dépend que de `zone` ; test « interruption de l'animation » de `ui-testing`.
- [Deux changes modifient « Navigation 3 paliers »] → règle de fusion documentée dans `proposal.md` ; l'implémenteur du second reprend le texte du premier archivé.
- [Liste cachée figée montrant un état obsolète] → l'état `hidden` de chaque ligne est vivant, seule la composition est figée ; elle est recalculée à chaque entrée dans la catégorie (D5).
- [Ordre d'« Apps sources » obsolète quand les compteurs changent] → assumé : l'ordre est figé tant que la catégorie est active (après l'éventuel retri unique), pour que les lignes ne bougent pas sous le focus ; il est recalculé à la prochaine entrée.
- [Observateur du TV Provider armé pendant l'affichage de l'accueil] → c'est le même observateur, désormais actif tant que l'accueil est au premier plan au lieu des seuls réglages, et arrêté en arrière-plan (D7) ; l'antirebond existant (500 ms) borne les relectures. À vérifier sur la TV de test (5.3) : aucune saccade de l'accueil lors d'une publication de programmes, et aucun comptage pendant la lecture dans une autre app.
- [Verre du dock actif pendant le défilement] → décision de Sygix (D3) : pas de changement d'aspect du dock ; le coût du flou pendant 400 ms est à mesurer sur la TV (5.1).

## Migration Plan
- Déploiement : aucune étape ; la clé `hidden_apps_dates` est créée au premier masquage après mise à jour. Les apps déjà cachées restent cachées, sans date, en fin de liste.
- Retour arrière : une version antérieure ignore `hidden_apps_dates` et continue de lire `hidden_apps` ; rien à défaire.
- Tests : `LauncherPrefsTest` avec un DataStore pré-rempli au format ancien (ensemble seul) → `hiddenWithDates` renvoie `null` pour ces apps, le catalogue les exclut toujours ; masquage puis réactivation puis masquage → une seule entrée de date, la plus récente.
